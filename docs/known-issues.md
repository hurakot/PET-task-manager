# Ограничения и планы

Что стоит знать о текущей версии и что можно улучшить.

## Нет миграций БД

Таблицы создаются через `create_all` при старте. Он создаёт только **новые** таблицы и не трогает существующие.
Если добавить или изменить поле в модели, на сервере с уже созданной базой оно **не появится**.

Сейчас: при изменении схемы — `docker compose down -v` (удаляет все данные) или ручной `ALTER TABLE`.
План: подключить Alembic.

## Безопасность

- Регистрация открыта для всех.
- Нет ограничения частоты запросов к `/users/token` — пароли можно перебирать. Для продакшена — rate limit (например, в nginx: `limit_req`).
- Нет требований к сложности пароля.
- Пустой `SECRET_KEY` не отвергается при старте. Можно добавить в `config.py`: `SECRET_KEY: str = Field(min_length=32)`.
- Нет refresh-токенов: после истечения access-токена нужен повторный логин.
- `/docs` и `/redoc` открыты публично.

## API

- `POST` возвращает `200`, а не `201 Created`.
- `DELETE` возвращает `200 {"ok": true}`, а не `204 No Content`.
- Нет CORS — если появится фронтенд на другом домене, понадобится `CORSMiddleware`.

## Эксплуатация

- Приложение за nginx не видит реальный IP клиента в логах uvicorn. Исправляется флагом `--forwarded-allow-ips="*"` в `CMD` Dockerfile (безопасно, т.к. порт 8000 открыт только на `127.0.0.1`).
- Бэкапы БД не автоматизированы — см. раздел «Бэкап» в [deployment.md](deployment.md).
